# Getting Started

## Prerequisites

- [Node.js](https://nodejs.org/) (for npm install)
- A terminal emulator (Windows Terminal, iTerm2, etc.)
- On Windows: [Git for Windows](https://git-scm.com/download/win) (includes Git Bash, recommended for cd tracking)
- [Claude Code](https://docs.anthropic.com/en/docs/claude-code), Codex, and/or GitHub Copilot CLI (optional, but that is the point)

Only needed when building from source: [Rust toolchain](https://rustup.rs/).

## Installation

### Download binary (recommended)

Grab the binary for your platform from [Releases](https://github.com/knmgn/renga/releases) and put it on your `PATH`. The command is `renga-cp`.

This fork publishes no npm package — upstream's `@suisya-systems/renga` installs as `renga` and is unaffected, so the two can sit side by side.

If you want Claude Code, Codex, or Copilot panes to talk to each other or control panes from inside the client, register renga's MCP server once per client:

```bash
renga-cp mcp install --client claude
renga-cp mcp install --client codex    # if you want Codex peers too
renga-cp mcp install --client copilot  # if you want GitHub Copilot CLI peers too
```

That exposes the built-in `renga-peers` network and pane-control tools such as `list_panes`, `spawn_claude_pane`, `spawn_codex_pane`, `spawn_copilot_pane`, `inspect_pane`, and `send_keys` inside the selected client.

### From source

```bash
git clone https://github.com/knmgn/renga.git
cd renga
cargo build --release
```

The binary will be at `target/release/renga-cp` (or `renga.exe` on Windows).

## First launch

```bash
renga
```

You'll see a terminal pane with your shell, a file tree sidebar on the left, and a status bar at the bottom.

## Basic workflow

### 1. Start Claude Code, Codex, or Copilot the peer-aware way

Press `Alt+P` in a terminal pane. renga inserts the peer-enabled Claude launch command for you; review it, optionally append args, and press `Enter`.

If you prefer the CLI path, `renga-cp split --role claude` and `renga-cp new-tab --role claude` open a new pane and auto-launch Claude Code with the same peer wiring.

The pane border turns orange when Claude Code is running — green for Codex, purple for GitHub Copilot CLI.

If you want a Codex worker, make sure `renga-cp mcp install --client codex` has been run once, then launch plain `codex` in a pane or let an orchestrator call `spawn_codex_pane`. A GitHub Copilot CLI worker is the same shape one client over: `renga-cp mcp install --client copilot`, then plain `copilot` or `spawn_copilot_pane`. Copilot asks for folder trust — and, in a directory it has seen before, which session to restore — before its composer appears; renga will not answer those dialogs for you, so clear them once with `send_keys` or by hand.

### 2. Split panes

Press `Ctrl+D` to split vertically, or `Ctrl+E` to split horizontally. Each new pane gets its own independent shell.

For a second Claude worker, press `Alt+P` again in the new pane instead of typing `claude` manually. That keeps the worker on the same `renga-peers` network.

### 3. Browse files

Press `Ctrl+F` to focus the file tree. Navigate with `j`/`k` and press `Enter` to preview a file with syntax highlighting.

### 4. Switch between panes

Use `Ctrl+Right` / `Ctrl+Left` to cycle through sidebar, preview, and terminal panes. Or just click.

### 5. Let Claude orchestrate other panes

After the MCP server is installed for a client, a pane can call tools like `list_peers`, `send_message`, `list_panes`, `spawn_claude_pane`, `spawn_codex_pane`, `spawn_copilot_pane`, `inspect_pane`, `send_keys`, and `poll_events`. Claude receives peer pushes as `<channel>` tags; Codex and Copilot drain them with `check_messages`. That is the core renga workflow: one pane can launch workers, inspect their prompts, and coordinate them without leaving the conversation.

See [Peer Messaging](/en/peer-messaging) for the full tool surface.

### 6. Quit

Press `Ctrl+Q` to quit renga. All shells are terminated cleanly.

## Shell detection

renga automatically detects your shell:

| Platform | Priority |
|----------|----------|
| **Windows** | Git Bash → PowerShell |
| **macOS** | `$SHELL` (usually zsh) |
| **Linux** | `$SHELL` (usually bash) |
