## 0. TL;DR（最有力仮説）

複数の独立した「旧補正レイヤー」が競合しているのではなく、**1 つの中核メカニズムが複数の経路で誤発火する**のが残存揺れの正体だと考えられる。

> **中核メカニズム:** `resolve_claude_caret`（`src/ui.rs:1257`）は、#257 で追加した **Tier 4（ハードウェアカーソル信用）が何らかの理由でバイパスされると、必ずレガシーの「最右非空白セル + 1」フォールバックに落ち、キャレットを入力末尾（end-of-input）へ再ピン留めする。**

Tier 4 がバイパスされる経路は **3 つ**ある（後述トリガー A / C / E）。そして **揺れ(ジッタ)** は、これらバイパス条件がフレーム間で **トグルする**ことで発生する — 1 フレームは Tier 4 が効いて正しい位置、次フレームは条件が崩れて末尾ピン、と交互に描画されるため、キャレットが正位置と末尾の間を往復して見える。

これは発注時の仮説どおり旧補正レイヤーが原因だが、性質は **「二重補正(同一フレームで2箇所が書く)」ではなく「前提失効 + 旧Tierの先取りシャドーイング(stale-tier shadowing)」**である。renga 内に同一カーソル状態を同一フレームで二重に書く箇所は確認できず、描画系とオーバーレイ系は明示的に last-write-wins（`src/ui.rs:938-944`）で分離されている。

**重要な限界:** 「v1.3.2 以降も残存揺れがある」というのは本タスクの**仮説（前提）**であり、本リポジトリ内に再現ログ・bug report は存在しない。本レポートの競合点はすべて**コードから演繹**したものであり、3 トリガーのうち実際にどれが発火するかは、現環境では実行できなかった再現実験での切り分けを要する。

## 2. 中核メカニズムと競合点（ファイル:行 + 根拠）

### 2.1 中核: Tier 4 バイパス → 末尾再ピン

`resolve_claude_caret`（`src/ui.rs:1257-1280`）の制御フロー:

```
1. find_prompt_row → None なら関数全体が None（→ L5 キャッシュへ）
2. Tier 1: prompt_row..=last の全セルを反転走査 → ヒットしたらその列を返す   ← レガシー前提
3. Tier 4: !hide_cursor() かつ cur_row が [prompt_row..=last] 内 → vt100 カーソルを返す  ← #257
4. 最終フォールバック: (last, pick_caret_col_on_row(last))                       ← レガシー前提
```

`pick_caret_col_on_row`（`src/ui.rs:1203-1223`）の最終段は **「最右非空白 +1、無ければ col 2」＝ 末尾ピン**。つまり Tier 1 がヒットせず、かつ Tier 4 が条件を満たさないと**必ず末尾へ再ピン**される。#257 のコミットメッセージ自身がこのフォールバック（rightmost non-blank + 1 への落下による末尾ピン留め）を名指ししている。

注目すべきは、**反転走査が 2 箇所に焼き付いている**こと: `resolve_claude_caret` の Tier 1（`ui.rs:1261-1267`）と `pick_caret_col_on_row` の先頭（`ui.rs:1205-1209`）。レガシー前提が二重に残るため Tier 1 シャドーイングは是正漏れしやすい。

### 2.2 Tier 4 がバイパスされる 3 トリガー

#### トリガー A — 入力ブロック内に「キャレット以外の」反転セルがあると Tier 1 が先取りする
`src/ui.rs:1261-1267`

Tier 1 は入力ブロック `[prompt_row..=last]` の**全セル**を反転走査し、最初に見つかった反転セルの列を**無条件で返す**（Tier 4 へ到達しない）。v2.1.x がキャレット以外の用途で反転セルを描く場合（選択ハイライト、`[Pasted text #N]` プレースホルダ強調、補完候補ハイライト、一時描画など）、Tier 1 がその列を掴み**正しいはずの hw カーソルを無視**する。
- **根拠**: Tier 1 が Tier 4 より前で early-return する（`ui.rs:1261` の `for ... return Some`）。
- **前提の検証状態（未確認）**: 「v2.1.x が入力ブロック内に反転セルを一切描かない」かは本リポジトリ内に裏付けが無い。#257 の根拠は「キャレットを反転セルで描かなくなった」であって「反転セルを一切使わない」ではない。ここが本仮説の最大の未確認点。

#### トリガー C — `screen.hide_cursor()` が true だと Tier 4 が丸ごとスキップされる
`src/ui.rs:1273`（`if !screen.hide_cursor()`）

Tier 4 は `!screen.hide_cursor()` を要求する。一方 `claude_pane` 経路自体は `should_track_claude_caret` の `(claude_ever_seen && hide_cursor)`（`ui.rs:1065`）でも成立し、`show_cursor = is_focused && (!hide_cursor || claude_pane)`（`ui.rs:955`）で描画される。→ **「Claude が一時的にカーソルを隠す」フレームでは描画は続くが Tier 4 はスキップされ末尾ピンに落ちる**。v2.1.x がストリーミング中に DECTCEM を一瞬 hidden にトグルすると、そのフレームだけキャレットが末尾へ飛ぶ。
- **根拠**: L1（旧前提=Claude は隠す）と Tier 4（新前提=隠さない限り信用）が DECTCEM 状態について**逆向きの前提**を持ち、同じ `hide_cursor()` ビットで分岐している。

#### トリガー E — ブロック境界誤判定で `cur_row` がブロック外と判定される
`find_prompt_row`/`resolve_input_row_last`（`src/ui.rs:1148-1197`）、ゲート `src/ui.rs:1275`

Tier 4 は `(prompt_row..=last).contains(&cur_row)` を満たす時のみ発火する。`prompt_row`/`last` は**レガシーのヒューリスティック**（prompt グリフ集合 `CLAUDE_PROMPT_GLYPHS`、`col 0 が空白 && 非空白あり` の継続行判定）で決まる。v2.1.x が入力ボックスのレイアウト/インデント/グリフを変えていると境界がずれ、実カーソル行がブロック外と判定され Tier 4 がスキップ → 末尾ピン。
- **根拠**: 新 Tier の正しさが**旧ブロック検出器に結合**（Tier 4 は独立に prompt 行を探さず `prompt_row..=last` をそのまま使う）。検出器の前提（`ui.rs:1082-1089`）は v2.1.x 以前のもの。

### 2.3 二次的な競合・ハザード

- **L5 キャッシュの stale 描画** (`src/ui.rs:992-995`): `resolve_claude_caret` が `None`（prompt 行が一瞬隠れる等）のフレームでキャッシュ値を描く。hw カーソルが定常になった今、前フレームの編集位置を一瞬描き残し揺れを増幅しうる。発火は `None` 時限定で寄与は小さいが、トリガー E と複合すると無視できない。
- **L8 二重実装のドリフト** (`src/input/overlay.rs:468` vs `src/ui.rs:1257`): pending-wrap 時に ui.rs 版は列クランプ、overlay 版は raw を返す（`overlay.rs:486-492`、テスト `overlay.rs:1038`）。**意図的**な非対称だが、将来 Claude 挙動が変わると 2 箇所同期が必要で、片方だけ直すと描画キャレットとオーバーレイ取り込み位置がずれ、オーバーレイを開いた瞬間に caret が飛んで見える。現状の直接原因ではないが申し送り対象。

## 3. 残存揺れ(ジッタ)の原因仮説

**静的に位置がずれるだけでは「揺れ」にならない。揺れ＝バイパス条件のフレーム間トグル。** トリガー別の再現条件仮説:

| トリガー | 揺れる条件（トグル源） | 想定再現シナリオ |
|---------|---------------------|----------------|
| A | 反転セルが**現れたり消えたり**する | テキスト選択中のキー操作、`[Pasted text #N]` 挿入直後、補完候補の点滅、シンタックス強調の再描画 → 反転セル有/無でキャレットが正位置と末尾を往復 |
| C | `hide_cursor()` がストリーミング中に**トグル**する | Claude 応答ストリーミングと並行して入力欄を編集 → カーソル一時隠蔽フレームだけ末尾へ飛ぶ |
| E | ブロック境界が一時的コンテンツで**揺らぐ** | wrap 直後、フッタ/ヒント行の出入り、ペースト直後の行数変動 → `last` が揺れて `cur_row` がブロック内外を出入り |

**最有力**: コードから演繹する限り**トリガー A（Tier 1 シャドーイング）が最も直接的**（Tier 4 より前で early-return し新前提を無条件に上書きする唯一の経路）。ただし A の発火は「v2.1.x が入力ブロック内に反転セルを描く瞬間がある」ことに依存し未確認。A が provably 無ければ重心は **E（ブロック誤境界）→ C（DECTCEM トグル）** に移る。

**切り分ける決定的問い:**
> v2.1.x の Claude は (1) 入力ブロック内に（キャレット以外でも）反転セルを描くことがあるか？ (2) 編集中にカーソルを隠す（DECTCEM hidden）フレームがあるか？ — (1) Yes なら A、(2) Yes なら C が live。両方 No なら E（境界誤判定）が主因。

## 4. 検証方法

### 4.1 既存トレースは 3 トリガーを判別**できない**（最優先の整備項目）

`RENGA_DEBUG_CURSOR_LOG` + `debug_log_caret_scan`（`src/ui.rs:978-982,1282-1313`）は `resolved`（最終座標）と**下位 8 行の `contents()` のみ**をダンプする。これでは:
- 生 `screen.cursor_position()` = **記録されない**
- `screen.hide_cursor()`（DECTCEM 状態）= **記録されない**
- 反転**属性** (`cell.inverse()`) = `contents()` に出ない＝**記録されない**
- どの Tier で解決したか = **記録されない**

→ 現状ログでは A / C / E が**区別不能**。**検証の前段として**、次タスクで以下を `debug_log_caret_scan` に追加する（修正本体とは別の「検証可能化」ステップ）:
1. 生 `cursor_position()` と `hide_cursor()` フラグ
2. ブロック `[prompt_row..=last]` 内の反転セルの有無・列
3. 解決された Tier 番号（1 / 4 / fallback）
4. `prompt_row` / `last`（ブロック境界）

### 4.2 切り分け実験手順（再現環境が用意でき次第）

1. **観測**: 拡張トレースを有効化し v2.1.x Claude ペインで揺れを再現（mid-line 編集 + ストリーミング、ペースト、wrap 境界、選択を各々試行）。「末尾ピンに落ちたフレーム」を抽出し、Tier 1 ヒット(A) / `hide_cursor` true(C) / `cur_row` 境界外(E) のどれかを判定。
2. **A の確認**: 入力ブロック内に反転セルが現れる瞬間がログに出るか。出れば A 確定。
3. **対照ビルド実験（旧補正の無効化）**: 検証用ローカルビルドで **Tier 1（`ui.rs:1261-1267`）を一時的に無効化**し揺れが減るか観測 → A の寄与を定量化。同様に Tier 4 ゲートから `!hide_cursor()` を外したビルドで C を、ブロック境界を実測値で固定したビルドで E を切り分ける。※すべて**検証用の使い捨てビルド**で、本タスクでは実装しない（読み取り専用制約）。
4. **対照群**: plain bash ペイン（#257 で症状なしと確認済み）を同手順で並走させ Claude 固有であることを再確認。

## 6. 次タスクへの申し送り（この場では実装しない）

1. **検証可能化を最優先**: `debug_log_caret_scan`（`src/ui.rs:1282`）に 生カーソル位置 / `hide_cursor` / ブロック内反転セル有無 / 解決 Tier / ブロック境界 を追加。これ無しでは 3 トリガーを切り分けられない。
2. **未確認の前提を確定**: v2.1.x が「入力ブロック内に（キャレット以外で）反転セルを描くか」「編集中に DECTCEM hidden になるか」。これが A/C の live 判定を決める決定的問い。sibling タスク `renga-windows-cursor-regression` の conpty プローブ生データが残っていれば引用して A の前提を裏付け可能（本リポジトリ内には未発見）。
3. **二重に焼き付いた反転前提**: 反転走査は `resolve_claude_caret`（`ui.rs:1261`）と `pick_caret_col_on_row`（`ui.rs:1205`）の **2 箇所**。F1 実施時は両方を整合させること（片方漏れ注意）。
4. **二重実装 (L8)**: `src/ui.rs:1257` と `src/input/overlay.rs:468` の同期が必要。pending-wrap 非対称は意図的仕様（保持必須）。
5. **制約遵守**: 上記対照ビルド実験はすべて**使い捨ての検証用ビルド**であり本リポジトリへの混入は禁止。修正は人間承認後の別タスクで。
